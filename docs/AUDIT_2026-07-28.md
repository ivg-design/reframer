# Reframer 0.10.0 audit and release readiness

Date: 2026-07-28
Status: build-3 remediation and background source/build validation passed;
foreground UI and live integration are explicitly deferred to the operator's
manual review; build-3 notarization and replacement installation are pending;
not a tagged or published release

## Scope

This top-to-bottom audit record covers playback and media lifecycle, exact and
estimated navigation, filters, security-scoped access, local/menu/global
shortcuts, AppKit window and panel behavior, external window management,
layout, accessibility, Help, DocC, public claims, tests, scripts, bundle
contents, CI, and release automation.

The audit separated source/build evidence from live interaction and Apple
distribution evidence. A successful unsigned build is not recorded as a
Developer ID, notarization, stapling, or Gatekeeper pass.

## Resolved findings

The release-candidate implementation now:

- presents video and controls in one canonical externally managed window, so
  macOS and Mosaic move or resize the complete unlocked overlay instead of
  targeting a detached control window;
- provides a preferred 1,060-point one-row layout, then reflows the same
  visible, accessibility-reachable controls from one 48-point row to two rows
  totaling 96 points below 920 points through the 640-point minimum;
- applies lock and unlock synchronously as one atomic window policy, eliminating
  the prior run-loop gap in which a queued window-manager write could race the
  frame snapshot, and uses the public status-bar tier above all ordinary
  application windows, including normal, floating, modal, and utility windows:
  pointer-transparent across video and controls, and neither movable nor
  resizable, regardless of the saved Always on Top When Unlocked preference;
- preserves the higher precedence of critical system-owned pop-up menus, drag
  UI, screen saver UI, and assistive-technology UI;
- refuses whole-overlay click-through unless the exact configured global
  Lock/Unlock chord is registered, then automatically unlocks and reports
  recovery if that registration is lost, conflicts, is suspended, or global
  shortcuts are disabled;
- restores pointer interaction, geometry controls, and the saved unlocked
  window level after the enabled global lock shortcut unlocks the overlay;
- renders bundled Help HTML as nonblank native AppKit content inside the
  sandbox instead of depending on a WebKit helper that cannot launch without a
  network entitlement;
- consumes held non-repeat shortcuts without dispatching again or leaking into
  AppKit menu autorepeat;
- retains unchanged Carbon registrations and their held state across lock/frame
  availability changes, so a held global lock chord cannot retrigger after
  reconfiguration;
- closes the key/frontmost auxiliary panel, resolves mixed-file drops
  consistently, labels every borderless window, announces dynamic failures,
  follows live accessibility display options, and keeps the full toolbar and
  long frame counts visible at the supported minimum width with explicit
  cross-toolchain slider heights;
- yields all application shortcuts to system sheets, preserves native
  documentation/table navigation while retaining contextual Escape, and
  exposes complete slider range/orientation, native text fields, individually
  reachable ready-state badges, and an enabled empty-state Open action;
- implements Quick Filter as a native AppKit pop-up, restoring conventional
  primary-click, keyboard-selection, and accessibility behavior;
- stops playback when a replacement is selected and lands the new video
  paused;
- makes playback intent main-thread-owned and revisioned, so a delayed playing
  callback cannot revive playback after a rapid pause; a generation-scoped,
  bounded two-second startup gate preserves Play through transient paused
  reports, settles on playing, and returns the model to Paused if AVPlayer has
  settled paused at expiry with no authorized seek or scrub handoff pending;
  EOF-replay and scrub seek completions resume only while their captured
  revision remains current, so a newer Pause always wins; a newer Play
  reauthorizes the existing in-flight seek rather than starting competing
  transport, delayed playing transitions are forced paused during scrub/seek
  handoff, and scrub end remains synchronous without an unprotected pause
  window;
- prepares one coherent usable video track for playback, Core Image filtering,
  metadata, and frame indexing, clips aligned audio to that video range, and
  calculates arbitrary transformed frame bounds as a rectangle;
- replaces the opaque 9.46 MB media sample with a 228 KB documented synthetic
  equivalent and adds playable synthetic MOV/M4V fixtures;
- reduces edit-list mapping from segment-by-sample rescans to binary source
  slices, bounds exact indexing at 2,000,000 samples, and retains a labeled
  estimate when that bound or sample-cursor support prevents an exact table;
- removes dormant sandbox-incompatible self-install code;
- pins GitHub Actions to reviewed Node 24 release commit SHAs, removes
  persisted checkout credentials, limits write permission to the release job,
  rejects forked code on the self-hosted UI runner, and verifies
  tag/version/changelog/main ancestry before the UI or signing stages;
- rechecks the release checkout plus local and remote tag targets against the
  immutable workflow event commit before publication;
- rejects locked UI-test sessions and forwards the explicit operator
  acknowledgement into XCTest using macOS Bash-compatible command assembly;
- runs repository validation with stock macOS system tools, eliminating the
  hosted-runner dependency on an uninstalled Homebrew `ripgrep`, and keeps
  unit-test weak-reference syntax compatible with the minimum Xcode toolchain;
- validates an exact universal runtime/Help resource allowlist, both
  architectures and deployment targets, source stamp, privacy allowlist, Help
  metadata, and Help-index freshness, while rejecting symlinks, unexpected
  signature contents, and unexpected executable-bearing bundle paths; a
  post-staple `Contents/CodeResources` entry is accepted only when Apple’s
  stapler validates it;
- confines release DerivedData to the packager's scoped temporary directory,
  unregisters its intermediate Reframer apps before cleanup, and rejects
  mismatched project build numbers or dirty-stamped release artifacts so
  packaging does not recreate stale Spotlight or LaunchServices results;
- unregisters temporary test apps and removes only sentinel-owned test
  DerivedData on every runner exit, preventing background validation from
  repopulating LaunchServices or Spotlight with retained builds;
- ships a current CoreSpotlight Help index and aligned Help version;
- records notarization JSON/ID and publishes checksums with the ZIP;
- replaces unusable private-reporting instructions and sanitizes obsolete
  public runner notes.

## Build-3 remediation validation

The build-3 source candidate replaces the split video/control windows with one
canonical overlay, introduces a responsive 1,060-preferred/640-minimum control
layout with a 920-point row breakpoint, applies an atomic public-status-bar
locked-window policy, migrates saved legacy geometry, and replaces WebKit Help
presentation with a bundled native AppKit renderer.

Candidate-specific automated validation after the synchronous lock-transition
fix passed:

- product-contract, repository, Help-index freshness, project/XIB, shell
  syntax, and whitespace validation;
- 237 deterministic unit/AppKit tests with zero failures or unexpected results
  in the 2026-07-29 00:26 UTC background run, including real AVPlayer startup,
  EOF replay with Pause-to-Play reauthorization, scrub transport suppression,
  scrub resume, and newer-Pause-wins lifecycle coverage;
- fresh unsigned Debug and universal arm64/x86_64 Release development builds
  for `0.10.0 (3)`, with macOS 15.0 in both slices; because this validation
  preceded the commit, its source stamp was correctly dirty, and the clean

There were no project-source, test-source, or analyzer warnings. Xcode emitted

## External release gates

The GitHub repository currently has no configured `reframer-ui` self-hosted
runner, `REFRAMER_UI_RUNNER_AUTHORIZED` variable, protected `release`
environment, release secrets, ruleset, protected `main`, tag, or published
release. Private vulnerability reporting is also disabled, so the working
security email is the current private channel. Repository Actions policy
currently allows all actions without enforcing full-SHA pins, and Dependabot
security updates are disabled; the source validator enforces pins in the
checked-in workflows, but repository policy remains an external defense-in-
depth gate.

Local Developer ID and notary credentials are available outside the
repository, and the historical build-1 review-candidate pipeline completed
successfully. That local evidence does not satisfy the missing protected
GitHub release environment, hosted secrets, self-hosted UI runner, tag, or
publication gates.
Multi-display removal, physical cross-application
registered-delivery/no-swallow observation, actual registration-conflict
recovery, drag/drop behavior, and a complete VoiceOver/display-accommodation
walkthrough also remain live smoke evidence.

The required GitHub and Apple setup is explicit in
[Release Process](RELEASE.md). Until the build-3 gates pass, `0.10.0` remains
`Unreleased`; no `v0.10.0` tag should be created.
